CTA button ideas - styles & hover effects

Six button treatments, each shown on all five backgrounds the landing page actually has and checked against the header pair underneath. Every button is live - hover it. The one beside it marked hover is the same button with its hover state forced on, so the two can be compared without moving the mouse.

The page currently ships four different CTA buttons in two different brand colours and three different corner radii. The point of this page is to pick one system for the header and the page together.

1. UI Kit ring

The header's own hover, scaled up: a 4px translucent ring blooms around the button and nothing moves. Already built and already in the UI Kit, so it is consistent with the header by definition. On the two dark surfaces the ring has to switch from purple to white, or it disappears.

With the header: the only idea that needs no adaptation - it is the header hover. The purple ring next to the blue Login ring is the one thing to check: two rings of different hues on one bar.

2. Lift and glow

The button rises 2px and casts a coloured glow. The most familiar big-CTA behaviour and the clearest "this is clickable" signal. A coloured glow is the one shadow that still reads on the navy and near-black bands, where a grey drop shadow does nothing at all.

With the header: the 2px lift is too much movement inside a sticky bar - the button appears to twitch as you pass over it. Use idea 1's ring at header size and keep the lift for the big page asks. That split is the recommendation.

3. Arrow slide

The button holds still and only the arrow moves right. The quietest of the six, and the only one that says where the click goes rather than just "this is a button". Best for mid-page asks that shouldn't outshout the hero.

With the header: works, but the arrow makes an already-long "Sign Up For Free" wider still. If this is the direction, drop the arrow at header size and keep the fill change only - the treatment survives, the width doesn't grow.

4. Sticker press

A hard offset shadow with no blur; on hover the button slides down into its own shadow, like something being pressed. The only treatment that belongs to the page's paper-wall language - tape, polaroids, sticky notes. Playful, and it will divide opinion.

With the header: this is where it falls down. The hard shadow reads as a mis-render at small size, and the Login button beside it would need the same treatment in blue, which is two hard shadows in a 72px bar. Lovely on the page, wrong in the header - which is why it isn't the recommendation.

5. Gradient sweep

Purple to blue - the Learn to Code and Learn to Build colours in one object - sweeping across on hover. Ties the button to the two-strands story the page tells. The risks: gradient buttons date quickly, and on the hero it competes with the background's own gradient.

With the header: the closest of the six to what the header already does - .ui-btn-primary is a blue gradient today, so this is that idea extended into purple. At 8px radius the gradient has very little room to read, though; it looks flat.

6. Outline to fill - the secondary

Transparent with a 2px border, filling solid on hover. This is the secondary button in every set, not a primary - it's what the hero's "See how it works" and the Login button should become. Two variants, because on the navy hero the outline has to be white rather than purple.

With the header: shown here as the pairing that comes out of the recommendation - outline Login beside a solid purple Sign Up. Cleaner than today's two-blue-buttons header, and the outline reads immediately as the lesser of the two actions.

The recommendation, assembled

Idea 2 for the big page asks, idea 6 for every secondary, idea 1's tighter ring for the small header button so it doesn't twitch inside a sticky bar. One system, three sizes, works on all five surfaces with no special case.
